# Internationalization (i18n)

## General Rules

- Never hardcode strings in UI — always use `stringResource(R.string.xxx)`
- All UI text must be extracted into string resource files
- No string concatenation in UI — use format strings with arguments instead

---

## Resource Files

```
app/src/main/res/
  values/strings.xml        English (default, 400+ keys)
  values/topbar.xml         Top bar titles (15 keys)
  values-vi/strings.xml     Vietnamese
  values-vi/topbar.xml      Vietnamese top bar titles
```

- `strings.xml` — all general UI strings
- `topbar.xml` — screen titles used in the top navigation bar only

When adding a new screen title, add it to **both** `strings.xml` and `topbar.xml` in all language folders if it's used as a top bar title.

---

## Supported Languages

| Code | Language | Folders |
|---|---|---|
| `en` | English | `values/strings.xml`, `values/topbar.xml` |
| `vi` | Vietnamese | `values-vi/strings.xml`, `values-vi/topbar.xml` |

When adding new keys, add to all language folders above.

## Key Naming Convention

Format: `category_subcategory_description`

**Not** screen-based — keys are grouped by **functional category**, not by screen.

### Categories

| Prefix | Usage | Examples |
|---|---|---|
| `all_` | Shared across multiple screens | `all_cancel`, `all_save`, `all_language`, `all_next` |
| `auth_` | Authentication screens | `auth_guest_screen_title`, `auth_forgot_pw` |
| `nav_` | Bottom navigation labels | `nav_home`, `nav_account`, `nav_dancers` |
| `account_` | Account/profile screen | `account_edit_profile`, `account_logout_desc` |
| `booking_` | Booking flow screens | `booking_confirm_title`, `booking_tab_pending` |
| `dancer_` | Dancer-related screens | `dancer_detail_about`, `dancer_detail_book_now` |
| `error_` | Error messages | `error_no_internet`, `error_blank_email` |
| `msg_` | Success/info messages | `msg_cancel_reason`, `msg_contact_us_success` |
| `top_bar_` | Top bar screen titles (in topbar.xml) | `top_bar_my_booking`, `top_bar_change_password` |
| `introduce_` | Onboarding/intro screens | `introduce_title_1`, `introduce_description_1` |
| `lang_` | Language selection screen | `lang_select`, `lang_select_des` |
| `role_` | Role-related labels | `role_guest_title`, `role_manager_title` |

### Key format rules

- Lowercase, underscore-separated
- Start with the category prefix
- Be descriptive enough to identify usage without reading the value
- Numbered variants: `introduce_title_1`, `introduce_title_2`
- Format strings: `hello_s`, `exp_s`, `cases_s` (suffix `_s` for string args)

---

## Compose Usage

```kotlin
// Simple string
Text(text = stringResource(R.string.all_cancel))

// Format string with argument
Text(text = stringResource(R.string.hello_s, userName))
```

## Adding New Keys

**Before declaring a new key, always check `all_` keys first.**  
`all_` keys are shared across the app — reuse them whenever the text matches.

```
all_cancel, all_save, all_confirm, all_next, all_skip, all_close,
all_ok, all_loading, all_language, all_logout, all_delete, all_send,
all_change, all_message, all_view_detail, all_notification ...
```

If a matching `all_` key exists → use it, do not declare a new one.  
If the text is specific to a feature → declare with the feature prefix:

```
auth_login        ← specific to auth feature
booking_confirm   ← specific to booking feature
dancer_detail_about  ← specific to dancer detail
```

### Steps

1. Check `values/strings.xml` for an existing `all_` key that matches
2. If found → use it directly
3. If not found → add to `values/strings.xml` (English) and `values-vi/strings.xml` (Vietnamese)
4. If it's a top bar title → add to `values/topbar.xml` and `values-vi/topbar.xml` instead
5. Never duplicate keys

## Text Encoding Safety (mojibake prevention)

All resource files are UTF-8 without BOM. Mojibake has happened before — e.g.
`Search your history…` became `Search your historyâ¦` (a UTF-8 `…` re-decoded
as Latin-1 and saved back). Follow these rules to never reintroduce it:

### 1. Escape typographic punctuation in XML resources

Use XML numeric references instead of raw characters for punctuation that is
easily corrupted by encoding round-trips:

| Character | Write as | Never paste raw |
|---|---|---|
| … (ellipsis) | `&#8230;` | `…` |
| — (em dash)  | `&#8212;` | `—` |
| – (en dash)  | `&#8211;` | `–` |
| ' (curly apostrophe) | `\'` (plain ASCII) | `'` |

Language content itself (Vietnamese diacritics, Japanese, Korean…) stays as raw
text — it is the value, not decoration. Only typographic punctuation is escaped.

### 2. Never edit resource files through the shell

PowerShell's `Out-File`/`Set-Content`/`>` default to UTF-16/ANSI and corrupt
UTF-8 files. Always edit XML with the IDE or file-editing tools; if a script
must touch a resource file, read AND write explicitly with UTF-8 (no BOM).

### 3. Scan after bulk edits or external paste

After copy-pasting text from Word/Google Docs/web, or any bulk edit, scan for
mojibake markers:

```
rg -n "\x{00E2}\x{0080}" app/src/main/res     # broken …/—/quotes (always corruption)
```

Note: standalone `â`, `Ã`, `Â` in Vietnamese files are legitimate diacritics
(`Ngân hàng`, `QUÉT MÃ`) — only flag them in non-Vietnamese files, or when
followed by the invisible control range (the `\x{0080}` pattern above).

### 4. Fixing corruption

Replace the exact broken sequence with the intended character (or its numeric
reference) and re-save as UTF-8 without BOM. Do not "fix" by retyping the whole
string in a shell.
